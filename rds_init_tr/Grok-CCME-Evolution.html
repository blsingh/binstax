CCME · Design methodology

Absorb what state can decide. Escalate only what it cannot.

CCME is a harness in front of Claude Code. Its evolution was driven almost entirely by silent failures — successes and failures that looked identical until work was already lost. The methodology that resulted is not a feature list. It is a rule for rationing the operator’s attention.

A design thesis, distilled from the harness’s growth from fourteen files to a self-auditing control plane.

OneThe problem the harness solves

A coding agent starts every session cold. The interesting lever is not the prompt but the environment the session boots into. CCME treats that environment as the unit of design:

  • A profile is a directory holding a context file and domain-specific slash commands.
  • A launcher presents profiles as a menu, builds an isolated working directory of symlinks into the chosen profile, and starts the agent there.
  • Hooks fire at session start and at the end of every turn.

That mechanism is unchanged from the first useful version. Everything that follows sits underneath it. The growth was not primarily new capability; it was the machinery required to keep the mechanism honest under concurrency, recovery, and operator load.

TwoThe central rule

Engage the operator where the decision cannot be derived from state — and absorb everything that can, so those engagements stay rare enough to be worth reading.

Importance is not the test. A failed network push is a real failure; the harness detects it and deliberately declines to raise it, because a commit that already exists on disk will retry next turn. Waking the session for that would cry wolf. The test is whether the distinguishing fact lives anywhere in the system. If it lives only in the operator’s head, the system must stop and ask. If it can be recorded or derived, the system must record it and stop asking.

The rest of the methodology is the set of practices that make that rule enforceable.

ThreeSilent failure as the teacher

Nearly every structural change was forced by a silent success that produced a broken outcome. The pattern is always the same: an operation reports completion, the observable state looks normal, and the thing the operator needed is absent or wrong.

Early examples: a backup that archived the launcher and hooks but zero profiles, because find against a missing path exits cleanly and the loop appends nothing; a Stop hook that printed “Committed” without checking the commit’s exit status; a nested worktree that git worktree add created without complaint and onto which a day’s work was checkpointed under the wrong profile name.

The defect is not the failure itself. It is the indistinguishability of success and failure at the moment a human is listening. The fix, each time, was to make the quiet path speak — or to remove the path that required the operator to notice silence.

Methodological consequence

Prefer a written claim over a derived inference. Prefer an explicit refusal over a plausible-looking default. Prefer a loud non-event over a silent partial success. The harness is allowed to be quiet only when the operator’s judgment is not required.

FourDo not infer identity from location

The single most repeated class of bug was treating a path, a directory basename, or a process’s working directory as a reliable identity. Each fix’s blind spot became the next failure:

  1. Shared checkout, concurrent profiles. Launching a second profile switched the working tree out from under the first. Fix: one git worktree per profile; nothing switches branches at launch.
  2. Worktree copy of the launcher. A tracked script cannot infer its repository from its own location. Fix: ask git --git-common-dir, guarded so the answer must actually look like CCME.
  3. Two sessions of the same profile. One worktree per profile recreated the original collision inside a single name. Fix: occupancy, not existence — allocate the next free numbered instance rather than share.
  4. Occupancy still inferred. Walking /proc answers “does someone appear to be here,” not “who owns this.” Fix: a claim file written with the launcher’s pid (which survives the final exec claude); death is the release, staleness is decided by the kernel.

The generalisation, stated in the source: a tracked script cannot infer its repository from its own location, so ask git instead. Rotated, the same sentence covers profile identity, occupancy, and ownership. In every case the fix replaced a plausible derivation with a record that says the thing outright — and none of the four fixes asked the operator anything. Concurrency stopped being a rule the operator had to carry and became bookkeeping the system absorbs.

FiveCustody of the repository

The harness commits work. That makes ownership and branch discipline load-bearing, not optional.

  • Whose repository? Hooks decide ownership against the shared git common directory — the one identity a main checkout and all linked worktrees agree on. Outside CCME they are inert. Global registration without this check once staged and pushed every Claude Code session on the machine.
  • Which branch? Every session runs on wip/<profile>. The Stop hook checkpoints there every turn. main receives only squash-merged commits from /me-ship. Messy checkpoints, clean trunk. The per-turn trail is archived to eval refs rather than discarded, so agent (and operator) behaviour remains reviewable.
  • Three endings, not one. Ship promotes; clean discards content and resets onto main; scrap deletes branch, worktree, and session. Session-start reconcile refuses to guess on a dirty branch: unwanted and unshipped are byte-identical on disk. The distinguishing fact lives only in the operator’s head, so the harness declines.

The same instinct produced the structural inversion: CCME is a standalone control plane that operates on an external work tree. Cloning it yields tooling and none of the work. Memory is a third repository, because profiles describe how to work (shareable) while memory describes this operator (not).

SixWhen to interrupt

The Stop hook’s exit-code contract is the clearest statement of the central rule in the tree. Exit 0 means nothing to report — a checkpoint was made, or there was legitimately nothing to do, or the work is committed and only the push was deferred. Exit 2 means no checkpoint exists for this turn and a human must act.

# The dividing line is deliberately "does a commit exist", not "did everything
# succeed". A commit that has not been pushed yet is on disk and retries next
# turn; waking the session for that would cry wolf every turn on a flaky link,
# and a wake that fires constantly is one that gets ignored.

hooks/stop-autocommit.sh — the exit-code contract

Loudness is a budget. A false alarm spends it. The threshold is therefore not severity and not success; it is whether operator judgment is actually required this turn.

SevenGrow evidence, not just features

The harness grew an order of magnitude in size. The majority of that growth is tests, validation, documentation, recovery tooling, and an append-only audit ledger — not new user-facing capability. Correctness stopped being “it keeps working” and became measurable.

Practical consequences of that shift:

  • A pre-push gate runs the suite before main moves; CI detects what the gate cannot (--no-verify, clones without hooks). The gate is asymmetric: wip checkpoints cost nothing; the suite is paid at ship time.
  • The ledger is twenty rounds of adversarial self-review with immutable finding IDs, dispositions, and reasons. It has its own checker; the checker is under test. Findings are cheap to assert and expensive to verify — measurement has disproved several, which stay in the record with the premise marked false rather than being quietly dropped.
  • A gate its author cannot satisfy is a deadlock. New checks are run against the live tree before they are registered.
  • When a finding names one instance, enumerate the set. When a claim is false in one place, grep the claim, not the file.
  • A test that carries a copy of the code under test proves nothing; mutation leaves it green. Extract from the shipped file, anchored on surrounding comments so a mutation reaches the assertions.
  • Verifying the mechanism is not verifying the purpose. Widening a backup’s coverage to survive disk loss was correct for recovery and exactly wrong for the second question the same path set was answering — what is safe to hand to another person. The audit verified mechanisms and missed purpose; the operator caught both findings.

Evidence is the instrument that locates decisions that were never anyone’s to automate, and hands them back.

EightComments litigate, they do not describe

Early comments described behaviour. Current comments record what was tried, what broke, what was rejected and why, and what a future maintainer must not undo. Failed designs are buried in the source next to the code that replaced them, so the next change has to argue with the history rather than around it.

# Warn rather than edit their PATH. A recovery tool the user cannot invoke
# from memory when the harness is down is not a recovery tool.

claudelaunch.sh — a rejected alternative, kept as the reason

There is a cost. A comment that reads as a guarantee, when it is really a hedge, stops the next person from checking. The standing rule that came out of the ledger: a comment states intent; it never states behaviour. Read the code the comment sits on before reporting what it does. That clause is now inside the harness itself.

NinePrune what no longer earns its keep

Several mechanisms were correct for the tree they were written against and became wrong when something else changed. They were removed rather than left as dead weight or soft options:

  • Tracked launchpad symlinks (absolute paths; churned machine-specific state onto every branch). Now gitignored and regenerated on launch.
  • A global .active-profile marker (adequate for one session; wrong under concurrency). Superseded by per-session claim files.
  • Profile-from-basename derivation (lossless until numbered instances existed; suffix stripping then mangled legitimate names and drifted across call sites).
  • Tracked per-machine permission grants. Replaced by a drift gate and a prune at launch.
  • A security mitigation that was moot on a single-user box and cost lines defending a door that is not there. Reverted; the reasoning stayed in the ledger.
  • Archiving scrap branches to eval refs (made permanent the work the operator had just judged worthless).
  • Seeding every profile session with its cold-start brief (right once, noise thereafter). Moved on-demand; retained only for teams, where a lead that does not know it is a lead is not a team.
  • An unconditional torrent-and-seed side effect of backup. Publishing must never be a side effect of backing up; the path was later removed entirely after producing defects and never being used.

Removal is part of the methodology. A mechanism that no longer earns the attention it costs — operator or maintainer — is a liability, even if it still “works.”

TenWhat stays fixed

The conserved region is small and intentional:

  • Core mechanism. Profile → launcher → launchpad of symlinks → agent. Editing a profile’s source takes effect in the next session with nothing to re-run.
  • Markdown as substrate. Profiles, commands, teams, notes, and the ledger use the same header-directive idiom. The parser is now one function; the idea is original.
  • No dependencies beyond bash and python3. No install step. Clone and run.
  • Inventory at session start. The agent is told what tools and projects exist so it does not have to go looking. Filenames are now wrapped as untrusted data; the habit is not.
  • Single-operator threat model, written down and used. Findings that defend against a co-tenant the harness does not have are closed on that basis.

CCME is an augmentation harness, so the question its design answers is what the operator is for. The answer the code converged on is the rule stated at the outset: escalate only the decisions whose inputs are not in the repository; absorb the rest so those escalations remain rare enough to read. Failing loudly is the enabling mechanism, not the goal — you cannot route a decision to the operator that the system never surfaced. Evidence, written claims, explicit refusals, and litigating comments are the instruments that keep the quiet path honest and the loud path scarce.
